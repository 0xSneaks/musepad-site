The old game

How launches on the old pads actually run:

Sniped in the same block

A bot owns the cheap supply in the first slot. Retail buys after the markup.

Bundled before you saw it

One wallet, split across a private bundle, pre-loaded before the public sees the coin. Dumped on first buyers.

Dev dumped, you held the bag

Creator bags bought at zero, sold at the top. Fees farmed on wash volume. The platform takes a cut of all of it.

The MusePad rules

Eight rules the protocol will enforce. No admin key can bend them — including ours.

MusePad itself is still a vision — the launchpad is not built yet. Its funding coin, MuseRay, is live on Raypad now (see Funding). These are the rules MusePad will enforce when it exists.

RULE 01

One price per slot

Every buy in the same slot clears at one price. Speed buys nothing.

RULE 02

One buy per wallet per slot

Bundles are split and repriced atomically. No front-loading in one transaction.

RULE 03

Sealed orders, uniform fills

Commit-reveal at launch. Same book, same moment, for agents and humans. No private mempool edge.

RULE 04

No dev buy. No pre-allocation.

The creator owns zero tokens at launch. Any bag is bought on the open curve.

RULE 05

Creator rewards that can't be gamed

Creator fees cliff-vest. Unlocks key on holder count and token age — never volume.

RULE 06

One flat fee, declared up front

One fee. Split declared on-chain: buyback-and-burn, the agent fund, operations. Not editable at runtime.

RULE 07

One ticker, forever

Copycats and lookalike names are refused. The first launch of a name is the only one.

RULE 08

LP locked forever

At graduation, 100% of liquidity locks. No one can pull it — not the creator, not us.

Beyond the eight: everything customizable — pair anything with anything, custom tax on programmable tokens, and the anti-bundle tax schedule (high at launch, stepping down within seconds to a minute). Design rules for the pad being built, stated in Everything customizable above. The eight rules are the fairness floor under every custom launch.

How the launch works

The MUSEPAD launch runs on METTPAD — Meteora's Dynamic Bonding Curve (DBC). One added discipline: the launch transaction is inspected locally before anything signs it. Mechanics verified on-chain against real METTPAD launches.

STEP 01

Metadata is frozen first

Name, ticker, description, image, links — uploaded and read back before launch. What is staged is what mints.

STEP 02

The launch transaction is audited before signing

METTPAD builds the transaction server-side. Before signing, it is decoded and checked locally: expected programs only (System, SPL Token, Associated Token, Meteora DBC, Metaplex), platform fee to treasury exactly 0.025 SOL, creator set as fee claimer. Any mismatch stops the launch.

STEP 03

One signature, then it's on the curve

Creator signs once. Platform co-signs the mint. Dev buy: 0 — first buys are public.

STEP 04

Fees go to the creator — with the fine print stated

Curve tax: 1%. METTPAD takes no cut on top. Meteora's DBC program takes 20% of trade fees; the creator share is 80% of the tax, claimable in full. On-chain and public.

STEP 05

Graduation locks the liquidity

At 400 SOL market cap, the curve graduates to a Meteora DAMM v2 pool. Liquidity locked — Rule 08.

FAQ

Short answers, kept current with the diary.

Is MusePad live?

The launchpad itself is not built yet — it is a design vision, published so the rules exist in the open before any code does. What exists today is this page, the funding diary, and a token launch staged on METTPAD.

Is the MUSEPAD token live or trading?

No. It is staged — metadata uploaded and verified — but the launch has not been fired, so no official contract address exists. Any coin trading as MUSEPAD before a mint is published on this page is not this launch.

What is METTPAD?

A Solana launchpad built on Meteora's Dynamic Bonding Curve. Launches mint a fixed 1B supply on a curve and graduate to a DAMM v2 pool with locked liquidity. We evaluated it on-chain before staging — see "How the launch works" above.

When does MUSEPAD launch?

Only after the creator wallet is funded (≈ 0.0533 SOL all-in) and one explicit launch decision is made. No date is promised, and the launch will be announced here with its mint and transaction the day it happens.

Will the creator buy at launch?

No — the staged dev buy is 0, the same rule MusePad's own design demands of every creator (Rule 04). If the creator wallet ever buys afterwards, it buys on the open curve and the move is disclosed in the diary.

What do token holders get?

No rights, no revenue share, and no promise of returns — the same standard stated for MuseRay. The token funds and marks an experiment, built in the open. Memecoins are highly volatile and can go to zero.

Can a launch pair with something other than SOL?

On MusePad the pad — by design, not yet built — yes: pair anything with anything, any token as the quote asset. This token is the exception that proves the rule: MUSEPAD itself is staged on METTPAD paired with SOL, because that is the configuration chosen for it.

Is the tax the same on every MusePad launch?

By design, no. Tax is creator-set on programmable tokens — a parameter of the token, not a pad-wide rate. MUSEPAD's own staged tax is 1% on the curve, then 1% after graduation: one chosen setting.

How can I verify any of this?

On-chain. The diary logs every material step with transaction links — MuseRay's contract, its launch, and its exit are all checkable today, and MUSEPAD's mint and launch transaction will be added the same way.
